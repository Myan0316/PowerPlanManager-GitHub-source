## 2. 测试目标、范围与优先级

本轮优先确保：用户可以完成真实操作；所有失败均被正确识别；没有误改、误删、错误回滚或虚假成功；最终 EXE 与已验证源码一致。界面美化和重新设计另行安排，但影响点击、输入、读取、关闭的界面问题属于本轮范围。

测试覆盖当前功能，以及新源码中的恢复备份、草稿与异常处理。隐藏属性管理、批量修改、跨进程提权、崩溃恢复日志等尚未确认交付的能力列入条件用例：未实现时登记为功能缺口；不能记为“测试通过”，也不直接当作已有功能的运行 Bug。

| 优先级 | 含义 | 典型问题 |
| --- | --- | --- |
| P0 | 发布阻断，先验证 | 写错 GUID、误删计划、取消后仍写入、备份失败仍删除、失败却显示成功、启动或常规点击崩溃 |
| P1 | 当前承诺能力必须通过 | 输入边界、外部修改冲突、恢复失败、权限处理、主要兼容性、打包完整性 |
| P2 | 完善体验与长期稳定性 | 辅助操作、极端规模、资源增长、非主要环境体验 |

用例优先级表示执行顺序，缺陷严重度另行判断。同一 P2 场景若发现误写系统，缺陷仍应定为最高严重度。

测试方式：**M** = 模拟系统与故障注入；**R** = 真实系统只读；**W** = 隔离环境真实写入；**U** = 实际 GUI 交互；**B** = 构建与打包检查。包含 W 的 U 用例也在测试环境执行。

## 3. 测试前提与统一判定规则

### 3.1 固定测试对象

每次测试记录版本号、主脚本/核心模块/EXE 哈希、构建时间、Windows 完整版本、架构、PowerShell 版本、系统语言、账号权限和硬件类型。测试期间源码发生变化时，旧结果不能自动转移到新版本。

分别记录“模拟测试通过”“真实系统测试通过”“最终 EXE 通过”。代码行覆盖率和断言数量作为辅助信息，不替代操作与异常分支覆盖。

### 3.2 真实写入环境

优先使用有快照的 Windows 测试机或虚拟机。涉及电池、Modern Standby、厂商工具与硬件实际效果的项目使用对应实体设备，虚拟机结果不能替代这些项目。

记录原始计划 GUID、名称、全部可读设置、活动 GUID 和相关备份。测试使用带唯一运行 ID 的临时计划，并保存本轮创建的 GUID 清单；清理只处理本轮拥有且当前状态允许清理的对象。原有计划受保护，不按名称前缀批量删除。退出、失败与超时后均核对实际状态和残留项。

无权限、硬件不足、无法观察桌面等情况记录为 BLOCKED，注明原因。不能通过“跳过”获得全通过报告。

### 3.3 独立的结果依据

GUI 显示、业务函数返回值和真实系统状态分别核对。真实系统测试用独立查询结果或 Windows 电源选项交叉验证，避免写入函数和校验函数共用同一个错误解析器。

`powercfg /list`、`/getactivescheme`、`/query` 可用于检查列表、活动计划和参数；导入导出及 AC/DC 命令语义以 [Microsoft powercfg 官方说明](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options) 为依据。若验证隐藏设置，另记录所用枚举方式及其实际覆盖范围。

所有写操作都检查：操作前状态 → 实际命令及目标 → 操作后状态 → 备份/恢复状态 → GUI 反馈。至少核对目标计划、其他原有计划和活动 GUID。读取失败、超时或进程被终止时，结果可能未确认，不能直接断言“没有发生更改”。

| 显示 | 100% / 125% / 150% / 200% 缩放，小屏幕、多屏幕不同 DPI、高对比度 |
| 计划数据 | 1 个、多个、同名计划、嵌套括号名称、第三方计划、计划在运行期间增删改、模拟空列表和损坏输出 |

数值边界统一包含：空值、空格、0、最小值、最大值、最小值减 1、最大值加 1、合法与非法步长、负数、小数、科学计数法、超长整数、4294967295、4294967296、十六进制文本和全角数字。内部解析能力与界面允许输入的格式应分别定义；拒绝不支持的格式时不得改写系统。

计划名称按当前核心实现验证 1、128、129 个字符，以及全空格、换行、控制字符、Unicode、重名、前后空格。128 是当前实现限制，不宣称是 Windows 统一限制。文件大小同理，检查当前实现的 16 字节与 64 MiB 限制及相邻值，同时验证真实有效文件是否会被误拒绝。

## 6. 四条必须逐步复现的关键用例

### 6.1 BUG-003：枚举设置点击异常

1. 固定最终 EXE 哈希，启动并打开测试计划的设置编辑器。
2. 先选一个范围设置，再选一个枚举设置；本机存在“幻灯片放映”时包含该项。
3. 遍历所有行，重复鼠标点击、键盘切换、排序后选择及关闭重开。
4. 检查枚举显示名称、实际值、AC/DC 当前值及只读状态。
5. 捕获未处理异常、受控错误以及实际点击证据；无异常但显示错值也算失败。

通过条件：全过程无未处理异常，值与行一致，没有系统写入。mock 事件测试、真实 GUI 点击和最终 EXE 三层证据均完成后关闭 BUG-003。

### 6.2 AC 成功、DC 失败并遇到外部修改

1. 在模拟状态中令原值为 AC=60、DC=30，目标为 AC=120、DC=65。
2. 让 AC 写成功，DC 写失败，记录命令与状态。
3. 第一次运行保持 AC=120，期望恢复到 60 并核对；第二次在恢复前外部改 AC=155。
4. 第二次期望保留 155，DC 仍为 30，明确报告外部冲突。
5. 再注入恢复命令失败和恢复读回失败，验证不会显示“全部恢复”。

通过条件：恢复行为按实际状态决定；错误消息分别给出原始失败、恢复结果及备份位置。真实 Windows 中另做不依赖故障注入的备份往返恢复验证。

### 6.3 删除前备份失败

1. 使用本轮创建的非活动测试计划，保存初始列表与活动 GUID。
2. 模拟备份命令失败、零字节输出、文件不存在、落盘后不可读四种情况。
3. 在 GUI 确认删除，检查实际系统调用记录。
4. 解除故障后重试，验证备份成功才删除；将该备份导入新 GUID 并比较设置。

通过条件：四种故障下删除命令次数均为 0；原对象和其他计划不变；成功场景的备份真正可恢复。

### 6.4 最终发布包包含修复

1. 固定待发布源码和所有依赖哈希，完成核心及 GUI 回归。
2. 构建 EXE，解包核对主脚本、核心模块和启动器。
3. 将 EXE 复制到不含源码的目录，以普通权限启动。
4. 验证真实主窗体、逐行选择，以及创建→编辑→导出→恢复→删除测试副本。
5. 记录最终包哈希、系统环境、操作证据、原始计划前后差异及清理情况。

通过条件：交付包能独立运行且包含已测修复；真实状态符合预期；没有原有计划变化或未说明残留。

- 当前范围 P0 全部执行且通过；任何误写、误删、虚假成功、不可恢复数据损坏或常规操作崩溃均阻断发布。
- 当前承诺功能的 P1 全部通过。若缩小范围，需同步移除或禁用不满足的入口并更新说明，再按调整后的范围验收。
- 历史 Bug 每个都有复现依据、回归 ID 和最终包验证结果。
- 真实写入至少完成一个完整生命周期与一次备份恢复；原有计划检查无非预期变化。
- 最终 EXE 在独立目录通过，包内依赖齐全，哈希与报告一致。
- 兼容性只声明已测试范围；BLOCKED、NOT_RUN、未实现均显式列出。
- P2 遗留缺陷有影响说明、临时处理方法和后续安排，不能影响上述保护规则。

建议性能目标在基准测试机上锁定：普通点击 200 ms 内有反馈，常规启动和刷新各不超过 5 秒，单次系统调用默认超时不超过当前设计的 15 秒。以上为建议验收目标，不是已经测得的数据；测试报告需写明机器、样本量、中位数/最慢值及超时处理情况。
