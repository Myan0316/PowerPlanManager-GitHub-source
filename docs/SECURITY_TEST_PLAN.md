版本：1.0　日期：2026-09-27　对象：0.3.1 源码、启动器、便携包、构建与测试工具。

## 2. 架构、资产和攻击者模型

执行链：便携 EXE（IExpress）→ 解包的 C# 启动器 → Windows PowerShell → 主脚本加载 Core/UI → `powercfg.exe`、注册表只读接口、`powrprof.dll` 的属性写入接口。另有直接 PS1/CMD 入口。

需要保护的资产：原有计划及活动 GUID、全部 AC/DC 值、全机共用 Attributes、可恢复备份、用户选择与确认内容、管理员令牌所能访问的文件、发布包及其来源、测试结果真实性。

| 边界 | 不可信输入/可变状态 | 必须核对 |
| --- | --- | --- |
| 启动 → 代码加载 | 解包目录、相邻 PS1、工作目录、环境变量、启动参数 | 实际执行文件来源、目录 ACL、令牌、签名/哈希策略 |
| UI → 核心 → 原生进程 | 名称、GUID、数值、路径、外部查询文本 | 独立参数边界、严格类型和目标身份 |
| 低权限磁盘数据 → 提升进程 | `.pow`、属性 JSON、偏好、链接/重解析点 | 最终对象、内容、访问控制、读取与写入间竞争 |
| 计划编辑 → 全机状态 | 活动项、外部改名/删除/设置改变 | 写前快照、写后读回、回滚所有权 |
| 属性恢复 → 注册表 | JSON 中机器、节点、Before/After、Phase | 确认对象一致、仅隐藏位变化、冲突拒绝 |
| 构建 → 分发 | 暂存文件、EXE、散列、源码 ZIP | 内容白名单、整体版本一致、失败后旧版可用 |
| 测试 → 用户系统 | 替身、真实写入开关、清理目标 | 隔离可靠、原始状态保全、错误不误报 PASS |

攻击者分层：A1 能提供恶意文件/名称但不能改系统；A2 能在同用户普通权限下改用户目录或并发运行程序；A3 是另一个普通用户/会话；A4 能污染构建输入或分发渠道。已拥有管理员任意代码执行的攻击者不用于证明新的提权。

区分普通可靠性、同用户篡改、跨用户越权及提升进程消费低权限内容。替换源码后由同权限用户主动执行，单独不足以证明提权；必须记录低权限写入能力、受害进程令牌及新增权限效果。不将 `ExecutionPolicy Bypass` 或未签名本身直接定为漏洞。

源码中未识别到 HTTP 服务、登录会话、数据库、主动下载更新或遥测入口，故 SQL 注入、CSRF、服务端 SSRF 等暂记“不适用”，不能记 PASS。若运行观测发现监听、联网或新接口，立即补充范围；UNC 路径触发的网络访问属于本方案。

## 3. 方法、状态和风险规则

方法标记：S = 静态审查；M = 模拟/故障注入；R = 系统只读；U = GUI 实际交互；B = 构建与包验证；W = 隔离环境真实写入；X = 隔离环境对抗性文件/权限/竞争测试。M 的文件写入也必须限制在本轮工作目录；X 不能在日常用户目录投放测试链接或替换系统文件。

P0 先执行：可能越权执行、误写误删、备份无效仍继续、错对象恢复、失败伪报成功。P1：权限与输入边界、正常功能安全性、错误恢复、兼容性。P2：长期资源、体验及防御改进。执行优先级与最终严重度分别记录。

缺陷严重度：严重 = 经证实的高权限任意执行或广泛破坏；高 = 越权写入、原有数据不可恢复损坏、确认目标被替换；中 = 有限范围错误写入、持续拒绝服务或恢复失败；低 = 可恢复的局部异常、诊断与防御不足。按真实前提调整，不预填 CVSS 分数。

状态只能用：NOT_RUN（未执行）、PASS（所有子场景满足）、FAIL（存在反例）、BLOCKED（缺环境/权限/观测能力）、N/A（有可核验的不适用理由）。部分通过不能归并成 PASS。功能未实现记范围缺口，不能假装已测试。

每条用例拆出子编号，例如 `IN-02/quote-tail/launcher`；保留输入原始字节或转义表示、随机种子、夹具哈希、命令参数数组、退出码、stdout/stderr、实际读写对象、前后状态、耗时与清理结果。日志中的错误文本不能执行为指令。

## 4. 隔离、环境及独立判定

### 4.1 环境矩阵

| 维度 | 必测与边界 |
| --- | --- |
| 系统 | Windows 11 x64 主基线；Windows 10、ARM64、32 位进程作为条件兼容项，未测不宣称支持 |
| 权限 | 标准用户、管理员未提升、同账号提升；不同账号管理员、另一用户/会话；拒绝访问策略 |
| 宿主 | Windows PowerShell 5.1/STA；MTA、PowerShell 7 为异常/条件兼容输入，不默认支持 |
| 语言 | 简体中文、英文、系统 UTF-8 代码页选项；不支持语言必须安全失败 |
| 存储 | NTFS、只读目录、锁定文件、配额/磁盘满；FAT/exFAT/UNC/断开的可移动盘单列 |
| 路径 | 空格、中文、括号、单引号、双引号文本、尾反斜杠、长路径、ADS、设备命名空间、目录联接/符号链接/硬链接 |
| 硬件 | 台式机与笔记本、AC/DC、Modern Standby、厂商软件/企业策略；VM 不能替代实体效果 |
| UI | 100/125/150/200% DPI、小屏、多显示器、高对比度、键盘与鼠标、焦点变化 |
| 入口 | PS1、CMD、解包启动器、最终便携 EXE；普通启动与测试参数 |

P0 在主基线模拟层全部执行；触及权限边界的 P0 再做标准用户与提升用户、同用户与跨用户对比。其余维度按相关入口组合，不以一个环境通过代替整个矩阵。

### 4.2 真实写入与清理

W/X 在有快照的专用 Windows VM/测试机执行。启动前保存原有 GUID、名称、活动项、普通和隐藏设置、相关注册表 Attributes 的存在性/类型/完整 uint32 值、测试目录 ACL、产物哈希。电源值只修改本轮创建的非活动副本；切换测试使用等值副本并及时恢复。全机 Attributes 不能通过创建计划副本隔离，必须另用 VM 快照与逐节点基线。

创建的 GUID、文件、进程 PID+启动时间、链接和锁对象建立所有权清单。清理仅处理本轮清单内的对象；不能按名称前缀、同名进程或广泛目录匹配删除。每个最终路径核实在隔离根内；先移除本轮链接本身，再处理普通目录，不递归跟随链接。竞争中出现外部状态时停止盲目回滚，保留证据并登记残留。

磁盘满使用限额测试卷；掉电使用 VM 关闭；恶意可执行夹具只写隔离标记并退出；不修改系统二进制、不关闭防护、不清除系统日志、不在当前工作机注入崩溃。UNC 只使用受控测试共享，禁止把凭据发送到外部服务。

### 4.3 判定不变量

1. 每个写入与用户确认的计划/分组/设置 GUID、范围和值一致；取消时系统写入次数为 0。
2. 无写权限、输入不合法、目标失效、元数据不可靠或必要备份失败时，停止后续破坏性步骤。
3. 原有计划、其他设置及无关文件不变；导入恢复使用新 GUID，不自动激活。
4. 清除隐藏仅影响位 0；其余位、节点类型/存在性、父子节点和全部电源数值按约定保留。
5. 返回码为 0 不足以判成功。GUI、核心返回值和独立系统读回必须一致。
6. 超时/崩溃后的写入状态可能未知；先读回，不将“报错”当成“完全未写入”。
7. 回滚不得覆盖检测到的第三方改变；所有无法恢复的侧别、GUID、备份位置与实际状态可识别。
8. 文件原子替换只解决单个文件更新，不能默认保证多文件发布或电源写入的事务性。

M 使用独立状态模型与写调用日志，不调用产品解析器构造预期答案。W 交叉使用原始 `powercfg` 输出、独立解析/电源 API 或 Windows 电源选项；Attributes 用独立注册表只读查询。只保存同一个函数的输入输出不算独立验证。

## 7. 优先复现方案与静态线索

以下仅为 **HYPOTHESIS（待验证）**。位置以函数名为准，避免代码更新后行号失效。每次测试必须包含合法输入的正向对照。

### H-01：恢复确认与实际节点可能脱离（VS-05，P0）

依据：UI 缓存 `RestoreRecord` 并用当前条目名称确认；`Restore-PowerSettingVisibility` 在确认后重新按路径读取 JSON，写入其中 GroupId/SettingId。需验证确认对象是否与新读内容绑定。

最小流程：M 中创建 A/B 两节点且当前值都是 2，生成 A 的合法记录（Before=3、After=2）；打开 A 恢复确认。用同步钩子在确认返回后、读取前把同一文件换成 B 的合法记录，再继续。记录 `Set-PowerAttributeValue` 接收的节点；A/B 前后状态分别核对。正向对照是不替换文件时仅 A 从 2 恢复为 3。

失败条件：确认 A 实际写 B，即使 B 的记录格式与当前值校验均通过。后续 X 验证普通权限是否可写该路径、提升 UI 是否消费替换内容；只有后者的权限证据成立才进一步按越权影响分级。测试后删除本轮文件，不改真实注册表。

### H-02：目录字符串限制与真实文件对象可能不同（FS-03、VS-06、PK-06）

依据：属性记录使用 GetFullPath+StartsWith；备份/偏好/发布最终 IO 的路径检查未等同于重解析点解析。源码导出有显式重解析点检查，需要单独验证根目录及检查后的变化。

最小流程：在测试根中创建 `allowed` 与 `outside-sentinel` 两目录，保存后者哈希；只在 `allowed` 下创建本轮链接指向后者。分别测试根、父目录、最终文件，记录最终打开对象和哨兵哈希。M 先覆盖路径字面量，X 再覆盖真实文件系统。正向对照用普通目录完成写入。

失败条件：声明受限的内部写入/恢复越过边界或未授权改变哨兵。用户主动选择的普通导出路径本可在备份目录之外，不以此误报路径穿越。清理时先删除链接本身，不递归进入目标。

### H-03：可写脚本及解包目录的高权限消费（LA-01/02/04）

依据：启动器验证相邻脚本存在性后用 `-ExecutionPolicy Bypass -File` 加载，未见运行时脚本签名/哈希验证；打包时哈希比较不能直接证明运行时来源。

最小流程：复制发布包至专用 VM；记录解包目录所有者/DACL、启动令牌、各 PS1 加载时间。低权限进程仅尝试替换测试副本为写入本轮标记并退出的脚本；在合法启动链中观察是否执行及以何权限执行。DLL 场景先观察实际模块解析再选择无害探针，不假设 DLL 一定可劫持。

失败条件：证明较低信任主体可影响较高权限执行；只证明同权限用户能编辑自己脚本，归为部署信任/加固事项。完成后回滚 VM 并核对外部目录无残留。

### H-04：普通操作多阶段失效与崩溃恢复（TX-05/06/10）

依据：设置写入使用逐步校验和逐侧回滚；普通计划流程没有与属性 Prepared/Applied 相同的完整持久化事务记录。

最小流程：M 状态模型设原值 AC=60/DC=120、目标 AC=180/DC=240；AC 落盘后注入 DC 失败，再分别注入恢复失败/外部第三值/进程退出。每个分支核对顺序日志与最终两侧值。X 仅在本轮非活动副本重现进程退出与重启。

失败条件：覆盖已检测到的外部值、把部分成功显示为完全恢复、丢失必要恢复路径或误改原有计划。数值相同的 ABA 竞争单列机制限制，不由读回相等证明操作所有权。

### H-05：属性日志记账失败和重放（VS-07/08/09）

依据：先写 Prepared，再原生写入，再更新 Applied；恢复成功后更新 Restored。互斥名称为 `Local\PowerPlanManager.Visibility`。

最小流程：给 `Write-VisibilityRecord` 增加只在 M 中使用的第 N 次失败钩子，分别失败在准备、Applied、Restored；另在读取与写入之间并发改值。保存每一步文件正文和模型状态。X 再测试同/跨会话 mutex、占用与遗弃。

失败条件：未保存准备记录仍写入、写入成功但错误声称无改变、重复恢复覆盖外部变化、锁拒绝导致未处理崩溃。跨会话无互斥先记实际设计范围，再以可复现错误写入确认严重度。

### H-06：启动报告路径覆盖（LA-08）

依据：`StartupTestReport` 在发行主脚本中可用，计时器直接 `WriteAllText` 到调用者传入路径，未见存在性/扩展名/覆盖确认限制。

最小流程：在隔离目录建立非 JSON 哨兵，记录哈希；分别以 PS1 与启动器传该路径，观测报告行为、异常和退出码；再测试只读、相对路径、链接。仅在 VM 中比较提升上下文。正向对照使用新的合法报告文件。

失败条件：非预期覆盖或未经同意的高权限写入；命令调用者能自由执行同权限 PowerShell 时，不独立将该开关定为权限提升。报告功能兼容需求与发行面暴露分别登记。

### H-07：有限时间不等于有限内存/等待（RS-02/04、VS-10）

依据：核心双流 `ReadToEndAsync` 读到内存；核心有进程与流等待超时，但启动器等待子进程和读取结果无类似上限；属性备份列表逐个读取且无总数限制。

最小流程：独立探针产生受控输出，逐档增加到 64 MiB；另一探针派生继承管道的后代并退出。外层测试看门狗与资源限制终止本轮 PID，采集私有内存/句柄和耗时。GUI 正常生命周期不设“必须短时退出”的错误判定；仅测试退出后管道不关闭情形。

失败条件：超出第 8 节预算、退出后持续挂起、进程/内存不可恢复增长。超时能终止原生进程不能自动证明整个链无资源问题。

### H-08：发布文件分别成功但整体不一致（PK-05）

依据：本地发布依次更新默认 EXE、Core、UI、主脚本，再写散列；单文件回滚不代表所有文件统一回滚。

最小流程：复制工程至隔离目录，放入带唯一标记的完整旧版本；对每一次 Publish-File 和散列写入注入 IO 失败。失败后枚举各文件版本/哈希并测试默认 EXE 与脚本入口；核对归档是否足以恢复全套。正向对照完整成功发布。

失败条件：静默形成不兼容混合版本、误称发布成功或旧版无法恢复。该脚本是本地文件发布，不把它误写成已上传 GitHub Release。

## 8. 执行顺序、模糊测试和资源预算

1. **基线与隔离自检**：登记环境/哈希，先审查 QA-01/02/05；确认替身覆盖与拥有对象清单，建立证据目录。
2. **S/M 优先风险**：先复现 H-01/H-02/H-04/H-05/H-06，执行 P0 输入、解析、写入保护；最小反例立即登记。
3. **已有默认回归与新安全回归**：结果绑定当前源码，不能覆盖旧报告；每个缺陷加能在修复前失败、修复后通过的独立用例。
4. **R/U/B**：真实只读、人工确认和包验证；启动器/最终 EXE 重跑相关攻击面。
5. **W/X**：专用 VM 内验证权限、文件系统、并发、原生属性和故障恢复；实体机只承担 VM 无法证明的硬件效果。
6. **修复与验收**：关闭缺陷并验证清理，执行相关功能回归和完整默认套件，输出证据/阻塞项/剩余风险。

初始预算（测试判据，不代表现有性能承诺）：单个纯解析 1 MiB 夹具 2 秒内、16 MiB 夹具 10 秒内；默认原生命令 15 秒超时场景外层 25 秒看门狗；GUI 正常刷新 5 秒内，持续超过 2 秒不可交互登记体验/可用性问题；100 次窗体循环经预热及同等 GC 条件后，私有内存增长超过 50 MiB 或句柄超过 100 且持续上升则调查；每个模糊测试子进程内存 512 MiB、墙钟 60 秒上限。预算需记录硬件/正常基线，调整必须在看结果前说明理由，不事后改阈值使其通过。

随机测试固定种子并保存生成器版本；参数/数值与文本解析各至少 10000 样本，另以正常 `.pow`、JSON、查询文本作变异语料。竞争先用事件/屏障确定性暂停在具体调用间，再以 100 次随机时序补充；仅“等待若干毫秒”不足以证明覆盖指定窗口。失败样本缩减后纳入回归，不能只保存最终统计数。

## 10. 缺陷与证据模板

每个缺陷使用独立编号 `SEC-YYYY-NNN`，至少包含：

- 标题、关联用例/子编号、状态（线索/已复现/修复待复测/关闭）、优先级与严重度及理由。
- 版本/提交/文件哈希、环境、攻击者权限、用户交互前提、实际跨越的信任边界。
- 最小输入/夹具哈希、明确步骤、同步点/种子、预期与实际；注明 M/W/X 层级。
- 受影响函数、原始退出码/日志、前后状态、写入目标及次数、截图或必要进程/文件访问记录。
- 影响范围、正常对照、是否可重复、是否只在不支持环境触发、不能确定的事项。
- 本轮对象清单、清理/恢复结果、残留项及处置；修复建议、补充回归、修复前失败和修复后通过证据。

证据建议保存在 `artifacts/security/<run-id>/`，按 baseline/cases/findings/cleanup 组织；不要提交真实 `.pow`、完整机器标识和用户配置。报告引用相对证据路径、哈希与运行 ID，公开附件脱敏。若证据因 Git 忽略只在本机，明确标注可用性，不能让读者误以为随源码交付。

## 11. 验收门槛

文档验收：100 个唯一 ID、步骤/判据/方法明确、与真实代码和现有测试对应、静态线索与执行结果分开。当前交付仅满足文档阶段。

安全测试验收：适用的 P0/P1 在要求环境内均有结果；无未关闭严重/高危缺陷；误写误删、未授权代码执行、确认错对象、虚假恢复均阻断发布。任何 P0 BLOCKED 阻断完整安全验收。P1 的环境缺口也必须使对应支持声明保持未验收，不能靠忽略项获得全通过。

中低危残余风险需有影响说明、缓解方案和责任人明确接受；未接受前标记未关闭。所有写入轮次完成独立状态复核和清理；修复后最终包及默认入口重新验证。总报告分别列计划 100 项、已执行、PASS、FAIL、BLOCKED、NOT_RUN、N/A 与子场景覆盖，不能用断言数量计算安全覆盖率。
