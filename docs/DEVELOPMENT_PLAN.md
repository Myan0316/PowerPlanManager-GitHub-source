## 1. 项目目标与范围

开发一个中文 Windows 桌面工具，打开后自动读取当前电脑的电源计划，支持切换、创建、修改、删除及备份恢复。换电脑后重新发现当地的计划和设置，不需要修改 GUID 或重新编写程序。

“通用”指动态适配电脑已有的能力，不表示所有硬件都能提供相同功能，也不表示能强制开启系统、驱动或固件不支持的功能。

### 第一版功能

| 功能 | 用户可见行为 | 完成标准 |
| --- | --- | --- |
| 自动发现 | 列出计划名称，标记当前启用项；支持刷新、查看和复制 GUID | 不依赖固定计划 GUID、名称或中文命令输出 |
| 快速切换 | 选中计划后点击“启用” | 调用成功后重新查询当前计划，再更新标记 |
| 创建计划 | 选择已有计划作为模板，填写名称与描述 | 生成新 GUID；默认只创建，不自动启用 |
| 修改计划 | 重命名、编辑描述、修改常用及高级设置 | 编辑先保存在界面草稿中，点击“应用”后才写入 |
| 删除计划 | 展示计划名称及 GUID，明确确认后删除 | 删除前完成备份；正在使用的计划须先单独切换；禁止删除最后一个计划 |
| 常用设置 | 屏幕关闭、睡眠、处理器等本机存在且可编辑的设置 | 分开显示“接通电源”和“使用电池”；有名称、单位、范围和说明 |
| 高级设置 | 按类别浏览、搜索，包括系统隐藏的设置 | 缺少可靠取值定义的设置只读，不猜测或默认填零 |
| 控制面板显示管理 | 对选中的设置切换“在 Windows 电源选项中显示”，可恢复原状态 | 独立于计划参数编辑；说明该属性影响本机多个计划；不提供无差别全量解锁 |
| 备份与恢复 | 导出计划、查看本软件的修改记录、恢复指定备份 | 计划数据与显示属性分别备份；恢复前显示目标及变更预览 |
| EXE 交付 | 中文图形界面，免安装便携包 | 目标电脑不需要 Python、PowerShell 脚本环境或另装 .NET 运行时 |

第一版聚焦传统电源计划管理。“设置”应用中的电源模式、休眠功能总开关、设备唤醒权限、BIOS、超频、开机启动、按游戏自动切换和后台常驻不纳入本次范围。也不提供会批量清除现有计划的“恢复全部默认计划”。

### 关于隐藏选项的设计修正

“程序内展示隐藏设置”和“让控制面板显示隐藏设置”分为两个操作。前者默认只读取，不需要为了展示就修改注册表；后者才修改显示属性。微软提供了读取与修改设置属性的接口，隐藏标志是一个位标志，不能把所有 `Attributes` 无差别写成 `2`。[读取属性说明](https://learn.microsoft.com/en-us/windows/win32/api/powrprof/nf-powrprof-powerreadsettingattributes)、[修改属性说明](https://learn.microsoft.com/en-us/windows/win32/api/powrprof/nf-powrprof-powerwritesettingattributes)。

程序不会把“注册了一个设置”“允许写入”“已保存成功”和“硬件实际采用”混为一谈。对无法判断实际硬件效果的项目，说明其适用条件，不宣称能解锁性能。

## 2. 技术路线与兼容策略

### 建议方案

- **C# + WPF + .NET 10 LTS**：适合 Windows 桌面界面，便于组织状态、输入校验和异步操作。具体 SDK 与依赖版本在技术验证阶段锁定，发布时采用仍受支持的安全补丁版本。[.NET 支持策略](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。
- **Windows 官方电源 API 为主**：通过 `PowrProf.dll` 枚举计划、读取设置、复制、改名、写值、启用和删除，减少依赖本地化文本解析。创建以复制现有计划为基础，与微软的管理流程一致。[电源计划管理](https://learn.microsoft.com/en-us/windows/win32/power/managing-power-schemes)。
- **系统 `powercfg.exe` 为辅**：用于 `.pow` 导入导出及必要诊断。只运行 Windows 系统目录中的已知程序，不经 `cmd.exe` 或 PowerShell 拼接执行。[powercfg 官方说明](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options)。
- **自包含便携包优先**：用户解压后双击 EXE，无需安装运行时。单文件 EXE作为可选发布形式，需要额外验证原生库解压、加载路径及提权安全；不为减少文件数量牺牲稳健性。单文件也需要按处理器架构分别发布。[.NET 单文件发布说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)。

### 兼容范围

- 首发目标为 Windows 11 x64；Windows 10 x64 纳入兼容验证，具体版本以所选运行时的支持范围和实测报告为准。
- ARM64 独立构建、独立测试，通过后再声明支持；第一版不承诺 Windows 7/8、32 位系统及 Windows Server。
- 覆盖台式机、带电池笔记本及 Modern Standby 设备。Modern Standby 是不同的待机模型，不能通过显示几个高级选项就视为已转换成传统 S3 睡眠。[微软待机模型说明](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/modern-standby)。
- 中文、英文系统均不能依赖固定菜单文字；未知厂商设置保留系统名称和 GUID，缺少名称时允许只读查看。
- 设置枚举包含 `NO_SUBGROUP_GUID` 下的无分组设置，不能只读取常见的处理器、睡眠等分类。[枚举接口说明](https://learn.microsoft.com/en-us/windows/win32/api/powrprof/nf-powrprof-powerenumerate)。
- 未测试的系统或硬件，在发布说明中明确标为“未验证”，不把本机通过等同于全面兼容。

### 模块划分

| 模块 | 职责 |
| --- | --- |
| 界面与草稿 | 显示、搜索、输入、未保存提示、变更预览；不直接写系统 |
| 计划服务 | 组织创建、切换、编辑、删除及恢复流程，管理并发和操作状态 |
| Windows 适配层 | 封装原生 API、内存和句柄释放、错误码、系统进程调用 |
| 能力与校验 | 读取枚举值、范围、步长、单位、策略限制；判断可编辑性 |
| 备份与恢复 | 保存操作前状态、记录执行进度、校验备份、检测恢复冲突 |
| 权限边界 | 普通界面按需启动短时提权执行进程；严格限制其可执行动作 |

业务逻辑通过接口访问系统，测试时可以模拟访问被拒绝、部分写入失败及外部修改，而不必反复改动真实电脑。

## 3. 界面与使用流程

主窗口左侧显示计划列表，右侧显示所选计划的“常用设置”和“高级设置”。顶部提供刷新、新建、启用、重命名、删除和备份入口。当前启用计划与正在编辑的计划分别标识，避免误认。

设置区提供“接通电源 / 使用电池”两列、分类和搜索。高级页可切换是否显示系统隐藏项；每项显示描述、合法取值、单位和只读原因。没有电池的设备仍可查看系统存储的电池配置，但标明当前设备情形，不假装这些值正在生效。

底部显示修改数量，并提供“撤销未保存修改”和“应用”。批量应用前展示旧值、新值及目标计划。切换计划、刷新或关闭窗口时，若存在草稿，需要明确选择保存、放弃或取消，不能静默丢失。

“备份与恢复”用于选择具体备份和具体目标；“控制面板显示管理”独立展示，避免用户误以为显示开关只影响当前计划。界面支持键盘操作、系统高对比度及常见 DPI 缩放。

## 4. 安全设计与不可妥协的规则

### 4.1 权限与系统边界

1. 默认以普通权限启动；打开、浏览、搜索、导出和编辑草稿不会自动请求管理员权限。
2. 写操作先检查能力与策略，再依据实际结果处理权限。组策略限制与权限不足必须区别显示；组策略禁止时不尝试改注册表绕过。预检查不能替代执行时的错误处理。[权限检查接口](https://learn.microsoft.com/en-us/windows/win32/api/powrprof/nf-powrprof-powersettingaccesscheckex)。
3. 必须提权时，仅执行本次已经预览的限定操作，使用 Windows UAC，完成后退出提权进程。取消 UAC 不产生系统改动，也不丢失草稿。
4. 提权进程只接受固定动作类型、经过校验的 GUID 和有界参数，不接受任意命令、脚本、DLL 路径或注册表路径。通过受访问控制保护的通信通道传输请求，验证对端身份、请求时效及一次性操作标识；提权端独立重做校验。
5. 如果 UAC 使用另一个管理员账号，检测用户身份变化；涉及用户上下文的操作不得静默作用到另一个账号，第一版明确拒绝这种跨账号执行。
6. 原生系统 DLL 从系统目录加载；外部程序使用绝对路径和独立参数列表。计划名、路径中的引号、空格、中文、`&` 等只是数据，不能被解释成命令。
7. 不安装驱动或常驻服务，不添加计划任务，不降低 UAC，不更改注册表访问控制，不要求关闭杀毒软件。运行时不联网、不收集遥测。
8. 导出文件由普通权限进程写到用户明确选择的位置，已有文件须确认覆盖。若某项备份必须提权读取，提权端只使用受控备份目录，再由普通权限进程完成导出，不能成为任意管理员文件写入入口。

### 4.2 输入与数据校验

- 计划使用 GUID 定位；重名计划允许区分，名称不能用作唯一标识或直接拼成备份路径。
- GUID 必须格式正确且在执行前确认仍存在；数值必须通过类型、范围、步长和枚举检查，拒绝负数、溢出及无效组合。
- 时间明确区分秒、分钟和特殊值；只有该设置的定义确认后才把 `0` 显示为“从不”。百分比、超时等不得依靠经验猜测。
- 下拉选项绑定实际枚举值，不假定枚举值连续；读不到 AC 或 DC 值时显示“不可读取”，不能用零替代。
- 当前值不在已知合法集合中时，保留并标注原值，该项暂时只读，不因下拉框没有匹配项就自动改写。
- 对已知关联设置检查逻辑约束，例如处理器最小值不能高于最大值。不能判定的厂商扩展项只读。
- 导入文件、恢复记录和本地配置均视为不可信数据；限定大小、数量、格式版本、字段类型和目标范围，不执行其中的内容。

### 4.3 隐藏属性修改

只操作用户选中的具体设置，保留与隐藏状态无关的其他属性位。先分别保存设置节点与分组节点的原始状态，包括值是否存在、类型及数值。

特别处理：微软的读取属性接口在同时传入分组和设置时会返回两者属性的按位或，不能把这个合并结果当成设置自身原值写回。如果隐藏来自分组，先展示该分组的影响范围，不自动批量修改所有子项。[属性返回值的定义](https://learn.microsoft.com/en-us/windows/win32/api/powrprof/nf-powrprof-powerreadsettingattributes)。

优先使用官方接口写入；如果恢复“原本不存在的值”等情形确需直接处理注册表，只允许操作已验证电源设置路径中的 `Attributes` 值，不接收外部提供的任意路径。无法可靠取得或恢复原始状态时，该项保持只读。

恢复前再次核对当前属性，发现后来被系统或其他软件修改时提示冲突。属性备份仅用于原电脑，不跟随计划导入到新电脑。

## 5. 写入、异常与恢复机制

### 统一写入流程

1. **刷新并比较**：重新读取目标计划、当前活动计划及本次涉及的原值，与用户编辑时的快照比较；发现冲突先停止，保留草稿。
2. **验证完整批次**：所有目标、数值和权限条件都通过后才开始写，避免写到一半才发现输入无效。
3. **持久化备份**：保存操作前状态和待执行记录；备份写入、读取校验失败则不执行修改。简单切换记录切换前 GUID，参数修改和删除保存完整计划备份及字段快照，显示属性单独备份。
4. **有序执行**：一次只运行一个写任务，禁止按钮连点造成重复执行。逐项记录已完成的写入，必要时按关联设置的安全顺序调整。
5. **使更改生效**：修改当前活动计划时，在合适时机重新应用它；调用前再次核对活动 GUID，若已被外部切换则停止自动应用并报告实际状态。编辑非活动计划不自动切换。微软说明活动计划的值更新需要调用 `PowerSetActiveScheme` 才会生效。[设置写入说明](https://learn.microsoft.com/en-us/windows/win32/api/powersetting/nf-powersetting-powerwriteacvalueindex)。
6. **读回验证**：重新查询参数和活动状态；仅在符合预期时显示成功。保存成功不等同于测得硬件效果。
7. **失败处理**：停止后续写入，根据记录尝试恢复本次已改的项目，分别显示成功、失败、已恢复和待处理状态。

### 不承诺虚假的事务能力

Windows 电源设置的多项修改不作为一个数据库事务提交。程序实施备份和补偿恢复，但不能承诺断电、系统崩溃或权限突然变化时全部自动恢复。

恢复只处理本次涉及的字段。当前值仍等于本次写入结果时才自动补偿；若已经被其他程序改成第三个值，则停止覆盖并提示冲突。恢复也可能失败，必须留下可用备份和明确的人工恢复入口。

外部软件不受本程序的写入锁约束；即使写前比较、写后复核，也不能完全消除竞争。遇到计划被删除、切换或参数被厂商工具重写时，刷新真实状态，不无限重试或争抢控制权。

### 特定操作规则

| 操作 | 失败或中断时的处理 |
| --- | --- |
| 创建 | 复制后再改名和初始化；失败时仅清理本次新建且仍未启用、未被外部改动的计划；清理失败显示残留计划 |
| 切换 | 不做无条件自动回切；先确认当前状态及是否有外部修改，再提供切回原计划的操作 |
| 删除 | 执行前再次检查活动状态与剩余计划；删除后再次枚举；备份保留，恢复不默认启用 |
| 导入 | 交由系统解析 `.pow`，以新 GUID 创建未启用的计划，不覆盖已有 GUID；读取验证后再允许启用，失败时处理本次导入的残留 |
| 恢复参数 | 预览差异并检查本机设置存在性、类型和合法范围；不把不兼容字段强行写入 |
| 恢复已删除计划 | 恢复前核对 GUID 是否被重新占用；冲突时停止或明确导入为新副本，禁止覆盖同 GUID 的现有计划 |
| 程序异常退出 | 下次启动识别未完成记录并查询实际状态；展示恢复选择，不自动重放待执行修改 |
| 取消或超时 | 开始写入前可直接取消；写入期间在可确认的步骤边界停止，并核对结果；超时不等同于“没有改动” |

### 备份与日志保存

默认保存在当前用户的应用数据目录，程序所在文件夹只读时仍可使用。使用内部生成的操作 ID 作为文件名；写入采用临时文件落盘后替换，备份校验通过才标记完成。机器级恢复数据使用适当访问控制，提权进程不盲信用户可篡改的恢复记录。

完整计划备份使用 `.pow`；另存带格式版本的元数据，包括计划 GUID、名称、时间、操作类型、旧值/新值、状态和错误码。校验和用于检测损坏，不当作来源认证。

未完成操作的备份不自动清理；历史备份提供明确的容量和清理入口。日志只保留诊断必要信息，不默认记录个人文档内容，也不自动上传。用户复制 EXE 到新电脑时不自动迁移历史恢复数据。

| M0 技术验证 | 核实工具链、目标系统、原生 API、隐藏属性、设置元数据及权限边界；在隔离测试环境验证写入与恢复 | 技术验证记录；确定可编辑范围、发布形式和提权方式，关键问题有结论 |
| M1 只读原型 | 中文窗口、计划列表、当前状态、分类、搜索、常用/高级页 | 打开和浏览不修改电源配置；异常项不影响其他内容；可正常缩放和键盘操作 |
| M2 安全基础 | 校验器、错误模型、操作日志、备份校验、受限提权、单写入队列 | 模拟权限拒绝、备份失败、取消 UAC 均不会误写；恢复记录可追踪 |
| M3 基础管理 | 切换、创建、重命名、删除、导入导出 | 使用测试计划完成全流程，验证 GUID 定位、删除保护及失败清理 |
| M4 设置编辑 | AC/DC、合法值控件、变更预览、冲突检测、部分失败恢复 | 写入与读回一致；批量中途失败可准确说明实际结果；没有静默覆盖 |
| M5 隐藏项与恢复 | 程序内隐藏项编辑、控制面板显示管理、备份恢复界面 | 分组和设置属性不混写；保留其他标志位；恢复前校验目标与冲突 |
| M6 发布验收 | 兼容测试、安全检查、干净环境运行、自包含打包、文档 | 达到第 8 节发布门槛，交付 EXE便携包、源码及测试报告 |

先完成恢复和权限基础，再开放写操作；先验证单项写入，再开放批量编辑。每个阶段完成后记录已通过项、未通过项和限制，不用一个模糊的“功能已完成”代替验收。

## 7. 测试计划

### 自动化与故障注入

- GUID、重名、空名称、超长名称、中文、括号、引号及 shell 特殊字符不会改变目标或触发命令解释。
- 数值边界、溢出、步长、非连续枚举、秒/分钟转换、特殊零值及 AC/DC 分别写入均按定义处理。
- 隐藏属性组合、分组继承、值缺失、原值含未知标志位时，修改和恢复不损坏其他信息。
- 枚举某一项失败、设置元数据缺失、API 返回缓冲区不足或访问拒绝时，界面不崩溃，也不把未知数据伪造成合法值。
- 第 N 项写入失败、启用失败、读回不一致、备份损坏、磁盘满、恢复失败等路径均能准确记录部分结果。
- 编辑期间外部改值、删除计划、切换活动计划；用户重复点击、同时开多个窗口；均不能导致误删或无提示覆盖。
- 提权请求伪造、重放、超大载荷、未知动作、非法路径及跨账号身份均被拒绝。
- 导入文件损坏、格式版本不支持、目标 GUID 冲突、备份路径越界等情况明确失败且不覆盖已有计划。

### 系统集成与人工验收

| 环境/场景 | 主要验证点 |
| --- | --- |
| 普通用户、管理员、策略受限账号 | 只读可用、按需提权、取消行为、策略限制提示 |
| Windows 11 x64；Windows 10 x64 候选版本 | 接口、发布包启动和基本功能；实测版本写入报告 |
| 中文与英文系统 | 名称、单位和 GUID 识别不依赖中文文本 |
| 台式机、笔记本、Modern Standby | 动态能力、缺失设置、AC/DC及活动计划限制 |
| 只有一个计划、多计划、重名及厂商计划 | 选择准确、删除保护、列表刷新 |
| 中文路径、空格路径、只读程序目录 | 启动、备份、系统进程参数和日志位置 |
| 没有另装 .NET 的干净测试环境 | 自包含 EXE 可启动、无需联网安装组件 |
| 100%、150%、200% 缩放及键盘操作 | 控件不截断、焦点可见、确认操作可访问 |
| 强制结束、超时、休眠恢复、外部工具修改 | 状态不假成功、重新读取、未完成记录可恢复 |

写入、删除、控制面板属性及崩溃恢复测试优先在有快照的虚拟机中执行；涉及硬件行为的测试使用单独创建的测试计划和测试设备。默认不对用户正在使用的原始计划进行破坏性验证。

当前电脑只读验证不能替代真实写入测试；虚拟机测试不能替代所有笔记本和固件行为测试。无法获得的测试环境如实登记为覆盖缺口。

## 8. 发布门槛与交付物

### 发布前必须满足

- 能动态发现计划，不包含旧电脑的自定义 GUID 假设；启动和浏览没有电源配置写入。
- 创建、切换、修改、删除、导入导出和隐藏属性恢复都有实测记录；不能只测“成功路径”。
- 不存在已知的误删、命令注入、任意路径提权写入、静默覆盖、失败却提示成功的问题。
- 修改前备份可读取；至少验证一次实际恢复及一次恢复失败提示；明确列出哪些状态能恢复。
- 打包后的真实 EXE在干净目标环境验证通过，不能只以开发模式运行成功作为依据。
- 完成依赖漏洞检查和权限边界审查；新增依赖有明确用途，锁定构建依赖及 SDK，避免不必要的第三方组件。
- 测试报告列明系统版本、架构、账号权限、通过项、未验证项和已知限制。

### 最终交付

1. `电源计划管理器` 便携发布包，含可双击启动的 EXE及必要运行文件。
2. 完整源码及构建脚本，便于以后升级 Windows或运行时后继续维护。
3. 中文使用说明，包含基本操作、权限提示、备份位置和恢复步骤。
4. 测试与兼容性报告，以及版本变更说明。
5. 发布文件的 SHA-256 校验清单。

如果有可用代码签名证书，发布时签名；没有证书则明确标记为未签名，不把校验和描述成可信签名，也不承诺消除 SmartScreen 提示。

自包含程序需要随应用发布更新内置运行时。后续发现相关运行时或依赖漏洞时，重新构建发布包；第一版采用人工更新，不增加后台下载和自动执行更新组件。[自包含运行时的维护责任](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。

## 9. 当前决定与待验证事项

**已经确定的方向**：中文 GUI、动态发现、计划管理、AC/DC 编辑、高级隐藏项、可核验备份恢复、最小权限、EXE便携交付。

**M0 必须解决的技术问题**：本机及候选 Windows版本的接口行为、厂商设置元数据完整性、隐藏分组与设置的原始属性读取/恢复、权限及用户上下文、提权通信与依赖加载、导入导出的恢复一致性。

这些属于开发中的技术验证，不需要用户记忆或提供旧 GUID。验证中发现无法安全编辑的项目，将明确只读并说明原因；影响核心需求的限制记录到设计中，不用隐藏错误或强制写注册表来绕过。
